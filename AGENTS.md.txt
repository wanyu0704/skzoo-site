AGENTS.md — SKZOO 角色與週邊典藏展示網站
> 本文件是本專案的 AI 協作規範（Agent Instructions）。任何 AI 助理在新增、修改、重構或測試此專案前，必須先閱讀並遵守本文件。若使用者的最新明確指示與本文件衝突，應以最新指示為準；涉及既有資料刪除、檔名變更或破壞性調整時，仍須先指出影響並取得確認。
1. 專案定位與目標
專案名稱： SKZOO 角色與週邊典藏展示網站（暫用展示標題：SKZOO Collection）。
網站定位： 以 SKZOO 為主題的個人粉絲典藏與週邊展示網站；不是官方網站、購物商城或交易平台。
核心目標： 以溫柔、可愛且方便瀏覽的方式展示 8 個角色及目前 40 張週邊圖片，同時提供角色簡介、展開閱讀、商品詳情彈窗、收藏清單與返回首頁功能。
主要語言： 繁體中文（zh-TW），角色及品牌專有名稱維持原有英文拼寫。
技術選擇： 原生 HTML、CSS、JavaScript。優先維持零建置、零框架、低依賴、容易閱讀與維護的純靜態網站。
部署考量： 網站應可部署至 GitHub Pages 或其他靜態網站服務，不依賴後端、資料庫或需保密的 API 金鑰。
目前素材狀態： 使用者表示已在其電腦的 `assets/` 放置 40 張 PNG 圖片。AI 尚未取得或逐一檢查這些檔案；未實際檢查前不得聲稱圖片已存在於執行環境、均可載入或內容符合名稱。
2. 設計語言（強制）
2.1 整體風格
採用活潑可愛的手帳／貼紙風，融合韓系／日系柔和典藏感。
主色為溫柔淡粉色與奶油白，輔以少量淡紫、低飽和米色等柔和色調。
建議使用圓角卡片、細緻邊框、淡陰影、紙張或手帳質感、少量貼紙／手繪裝飾。
氣氛應輕盈溫暖，圖片仍是視覺主角；不可讓貼紙、背景或動態特效搶走商品焦點。
避免強烈螢光色、大面積純黑／鮮紅、過度複雜的背景與密集閃爍動畫。
2.2 參考配色（可因易讀性微調）
用途	建議色碼
主背景／奶油白	`#FFF9F3`
主題淡粉	`#F8DDE5`

色碼是初始設計參考，實作時須優先確保文字對比與可讀性。
使用 CSS 自訂屬性集中管理色票、字級、間距、圓角與陰影，不可在各處散落大量難以管理的重複設定。
2.3 動畫與互動
可以加入輕微的卡片浮起、按鈕回饋、展開轉場及柔和的 Hover 效果。
手機上不可仰賴 Hover 才能使用功能。
尊重使用者的 `prefers-reduced-motion` 偏好；減少或取消非必要動畫。
不得因動畫而造成畫面跳動、文字難讀或操作延遲。
3. 資訊架構與頁面排版
3.1 主站為單頁式
目前以單頁、依角色分區為正式架構，不預先製作八個獨立角色頁面。建議由上至下排列：
頁首／首頁入口： 網站名稱、簡短副標與主要導覽。
角色快速導覽： 8 個角色的導覽項目，可直接捲動至相應分區。
角色展示區： 依固定角色順序，依序顯示角色標題、簡短介紹、展開更多資訊控制及該角色的商品圖片卡片。
收藏清單入口與收藏檢視： 同一頁內提供清楚的入口，可檢視全部已加入收藏的商品。
頁尾： 簡單的網站說明與非官方粉絲作品聲明。
3.2 角色展示區
初始資料共有 8 個角色，每個角色 5 張圖片。
各角色都必須能從快速導覽定位到，不可只靠長時間捲動尋找。
每一角色分區至少包含：角色英文名稱、簡短介紹、可展開／收合的更多資訊、週邊卡片列表。
角色介紹未核實或未經使用者確認時，使用中性占位內容或保留待審狀態；不可把模型自行創作的設定當成官方資料呈現。
所有角色版型應共用同一組渲染邏輯，不要為每個角色複製貼上大量重複版面程式。
3.3 週邊卡片
預設卡片主資訊： 圖片＋商品名稱。
可加入低干擾的「加入／移除收藏」愛心按鈕；此操作不應使卡片變成資訊過度擁擠。
點擊商品圖片或商品資訊區，開啟商品詳情彈窗。
卡片布局必須在桌面、平板及手機寬度下自然換行，避免溢位、圖片變形、文字互相覆蓋。
若正式商品名稱未經核實，使用明確標示的暫定名稱（如「BbokAri 週邊 1（名稱待確認）」），不得自稱為官方名稱。
3.4 商品詳情彈窗
顯示大圖、商品名稱與已有且已確認的商品資訊；沒有資料的欄位應隱藏，不能自行補寫。
預留商品類型、系列、說明、備註等欄位，但初版不強制在卡片上顯示。
彈窗需有清楚的關閉按鈕，支援 Esc 鍵與合理的鍵盤操作；開啟時焦點進入彈窗，關閉後回到原操作位置。
彈窗開啟時避免背景內容被誤操作；畫面過小時內容可捲動，圖片保持原始比例。
在彈窗中同樣可以加入／移除收藏，狀態要與商品卡片同步。
3.5 收藏清單（初版必備）
「收藏清單」先定義為使用者在本站標記喜歡的商品／最愛清單，不代表已實際購買或持有。
不要求登入；以瀏覽器 `localStorage` 儲存收藏商品的穩定 ID。不要建立不必要的外部帳號、後端或雲端同步。
使用者可以加入、移除、檢視收藏；收藏為空時須有友善的空狀態提示。
商品卡片、商品詳情彈窗及收藏清單中的愛心狀態必須同步。
刷新同一瀏覽器的頁面後，收藏應持續存在；清除瀏覽器資料、無痕模式或更換裝置時不保證保留。
`localStorage` 不可用或資料損毀時，網站仍需正常顯示商品，並以適當方式降級處理；不能使整站崩潰。
僅存收藏 ID 等最低限度資料，不收集或傳送個資。
收藏檢視優先使用同頁區塊或切換模式，不在未經要求下新增獨立收藏網址或登入流程。
3.6 返回首頁（初版必備）
網站應提供清楚的「返回首頁」功能，從角色分區、收藏檢視等位置可回到單頁最上方的主頁區域。
建議頁首品牌標誌／網站名稱可點擊返回頂端；在較長頁面可有不遮擋內容的返回頂端按鈕。
若目前正在商品詳情彈窗內，先正確關閉彈窗，再返回頂端。
「返回首頁」不應誤導至外部網站、其他網域或清空收藏資料。

預設角色展示順序以上表為準；若要重排順序，應透過集中管理的資料順序調整，不得修改檔名。
5. 技術架構與資料集中管理
5.1 技術原則
只使用 HTML5、CSS3、原生 JavaScript，不預設引入 React、Vue、Tailwind、jQuery、資料庫或其他套件。
優先採取可直接部署的靜態檔案架構；若有引入新函式庫或建置工具的需求，必須先解釋必要性並取得使用者同意。
保持語意化 HTML、模組化 CSS、職責清晰的 JavaScript；避免把所有邏輯與資料塞在單一巨大檔案。
所有資料與畫面呈現應分離。不得在 HTML 中為 40 張商品圖手動重複撰寫 40 份結構。
5.2 建議的資料夾與檔案責任（不是現有檔案清單）
建議位置	責任

`index.html`	主頁 HTML 骨架及語意化容器

若拆分 JavaScript 檔案，須確保載入順序及部署方式可正常使用，避免在 `file://` 測試時因模組限制產生誤判；正式驗收以本地靜態伺服器或部署網址為準。
5.3 集中資料模型規範
角色與商品資訊應集中於單一資料來源（建議 `js/data.js`），至少能表達：
角色資料：
`id`：唯一且穩定的英文識別碼；作為錨點、篩選與資料關聯使用。
`displayName`：前端顯示用名稱，須精確保留使用者提供的拼寫。
`order`：顯示順序。
`shortIntro`：已確認的簡短介紹或明確的待確認標記。
`longIntro`：可展開資訊；允許未確認時留空。
`introStatus`：例如草稿／待審／已確認；不得將未審查資料當作完成品。
`sources`：撰寫角色資訊時所依據的來源紀錄（可含官方頁面網址與查核日期）。
商品資料：
`id`：全站唯一且穩定，新增與排序時不隨意重編；收藏功能以此識別商品。
`characterId`：對應角色 ID。
`imagePath`：指向 `assets/` 中的實際相對圖片路徑。
`displayName`：商品顯示名稱；無官方資料時必須清楚標示待確認。
`type`：週邊類型（例如吊飾）；可擴充，但不得僅憑檔名冒稱官方分類。
`series`、`description`、`note`：可選欄位；只在資料確定存在時顯示。
`order`：商品於角色區塊內的顯示順序。
注意： 程式資料欄位名稱為建議介面，未來可在不損害意義與相容性的前提下調整；角色 ID、商品 ID 與既有圖片路徑應盡可能保持穩定。
6. 角色介紹與內容可信度
初版每個角色需有簡短介紹＋可展開的更多資訊。
介紹內容可由 AI 根據可靠來源提出初稿，但必須交由使用者審核確認，才能視為正式文案。
查證順序優先使用 SKZ／SKZOO／JYP 的官方網站、官方帳號或官方發行資料；其他粉絲整理資料只能輔助交叉比對，不能當作官方設定。
清楚區分官方已證實資料、粉絲常見說法與創作性描述；不得混寫成無來源的「角色官方設定」。
不可捏造角色與成員關係、生日、性格、背景故事、尺寸、材質、商品系列或發售資訊。
若來源不足，使用「資料待確認」或省略欄位，而不是補上看似合理的內容。
引用資料時保留來源連結及必要的查證紀錄；不可直接整段複製他人的介紹文字。
網站應適當表明是非官方粉絲典藏展示，避免誤導為官方授權或官方商店；素材與標誌的使用須尊重權利人及適用的授權規範。
7. 響應式、無障礙與效能要求
7.1 響應式
必須支援桌上型電腦、平板及手機，不出現橫向溢位。
角色區塊與商品卡片採彈性網格；桌面可呈現多欄、平板適度減欄、手機優先 1～2 欄，按實際可讀性調整。
小螢幕上的導覽、收藏操作、展開內容及彈窗不得被遮住或變得難以點擊。
圖片以保持長寬比為原則，避免不當裁切 SKZOO 主體。
7.2 無障礙
正確使用標題層級、可點擊按鈕、圖片替代文字及清楚的操作標籤。
圖片 `alt` 至少描述角色與可確認的商品性質，無法判斷的細節不可編造。
導覽、展開內容、愛心收藏、返回首頁與彈窗皆須能使用鍵盤操作。
顏色不是傳達收藏狀態的唯一方式；提供文字或輔助技術可讀的狀態。
文字與背景需維持合理對比；互動焦點須可見。
7.3 效能與可靠性
商品圖片可採延遲載入，避免一次載入大量圖片造成首屏過慢。
圖片讀取失敗時顯示友善占位狀態，並保留商品名稱與其他操作；不要導致整區塊消失。
避免不必要的動畫套件、大型外部依賴與頻繁重繪。
對動態文案採安全文字插入方式，避免將未經處理的內容直接注入 HTML。
若新增功能需要網路連線、帳號或外部服務，須事先取得同意，不能悄悄加入追蹤或分析服務。
8. 未來擴充規則
8.1 新增週邊圖片或其他商品類型
確認使用者提供的圖片實際檔名及路徑。
在集中商品資料中新增紀錄，使用唯一且穩定的商品 ID。
指向正確的相對圖片路徑，不修改既有 40 張檔案。
依確定的商品類型填寫資料；不確定的內容標示待確認。
由既有通用卡片、彈窗及收藏機制自動支援，避免複製一整套頁面程式。
測試既有商品、收藏狀態與手機版排版不受影響。
8.2 新增其他 SKZOO 角色或分區
先檢查是否已有相同角色 ID 或相同名稱，避免重複資料。
在集中角色資料新增角色名稱、唯一 ID、顯示順序、介紹欄位及來源狀態。
新增對應商品資料與圖片路徑。
讓新的角色區塊與快速導覽由同一資料來源自動產生。
不得以新增角色為理由重命名、刪改或重新排序既有角色，除非使用者要求。
8.3 未來的篩選與搜尋
預留依角色、週邊類型、收藏狀態等條件篩選的資料結構。
篩選／搜尋是預留擴充功能，不是此次初版必須立即實作的完整介面；目前的角色快速導覽與收藏檢視仍屬必備。
新增篩選時應以資料欄位為依據，不能依賴檔名文字猜測商品種類。
篩選結果不得改變原有資料或清除收藏記錄。
8.4 未來的角色獨立介紹頁
目前不建立獨立角色網址或子頁，先以同頁展開式介紹滿足需求。
若未來使用者要求新增獨立角色頁，應優先重用同一份角色資料及共用的展示元件／樣式。
不要為每個角色維護互相矛盾的重複介紹內容。
